## Tech Stack

Expo 54, React Native 0.81, React 19, Expo Router 6, TypeScript 5.9, react-native-reanimated 4, react-native-gifted-charts for charting, AsyncStorage for persistence. Path alias `@/` maps to project root. TypeScript strict mode is enabled; typed routes and React Compiler experiments are on.

## Architecture

### Routing

Expo Router file-based routing in `app/`. The `(tabs)/` group creates three bottom tabs: Today (index), Challenges, Stats. Root layout (`app/_layout.tsx`) wraps all providers and defines the Stack. Full-screen routes outside tabs: `/login`, `/reset-password`, `/onboarding`, `/settings`, `/speed`, `/strength`, `/stats-speed`, `/stats-strength`.

### Provider Nesting (root layout)

`AuthProvider` > `UserProvider` > `HabitProvider` > `ChallengeProvider` > `ThemeProvider` > `Stack`

All four providers are at the root level so every screen (including /speed, /strength, /settings) can access all contexts.

### State Management — Three Contexts

**UserProvider** (`contexts/user-context.tsx`) — User profile with `activeHabitIds`, `schedule` (weekday assignments), `speedProtocol`, `strengthProtocol`, notification prefs. Access via `useUser()`. Profile persisted to AsyncStorage key `user-profile`.

**HabitProvider** (`contexts/habit-context.tsx`) — Daily habit tracking. Exposes `activeHabits` (all active), `todayHabits` (schedule-filtered for today), `weekLogs` (Map of last 7 days), `logHabit()`, `getHabitProgress()`. Logs persisted to `habit-logs-YYYY-MM-DD` keys.

**ChallengeProvider** (`contexts/challenge-context.tsx`) — Single active challenge at a time with multi-day duration. Supports multi-habit challenges via `habitIds[]`. Persisted to `challenges` key.

### Data Persistence (AsyncStorage)

All data is persisted to AsyncStorage with typed wrapper functions in `utils/storage.ts`:
- `habit-logs-YYYY-MM-DD` — daily habit completion logs
- `user-profile` — user settings and active habits
- `challenges` — challenge state array
- `speed-session-YYYY-MM-DD` — speed stick training sessions
- `strength-session-YYYY-MM-DD` — strength workout sessions
- `strength-last-workout-day` — last completed rotation day
- `strength-exercise-defaults` — carried-over weight/reps per exercise
- `speed-stats` — aggregate speed stats (driver PR, milestone tracking)
- `strength-stats` — aggregate strength stats (streak, exercise PRs)
- `queue-order` — learned habit queue ordering (avg completion hour-of-day)

Range queries use `AsyncStorage.multiGet()` via helpers like `loadSpeedSessionRange()` and `loadStrengthSessionRange()`. Date arrays generated by `dateRange()`.

### Scheduling System

`utils/schedule.ts` — `getScheduledHabitIds()` resolves which habits are active on a given date using weekday assignments from `profile.schedule.habitWeekdays`. Supports two modes per habit: specific weekdays or count goals (daily/weekly/monthly) with auto-generated weekday mapping via `profile.schedule.habitModes` and `habitGoals`. Default (no schedule) = all habits show daily.

### Theming

Dual light/dark mode with golf-green palette (`#2D6A4F` primary, `#52B788` accent). Colors defined in `constants/theme.ts`. Use `useColors()` hook for current scheme colors. Navigation theme overrides in root layout.

### Platform Differences

- **Icons:** `components/ui/icon-symbol.tsx` maps SF Symbol names to MaterialIcons (Android/web). The `.ios.tsx` variant uses native SF Symbols. Add mappings to both files for new icons.
- **Color scheme:** `hooks/use-color-scheme.web.ts` adds SSR-safe hydration check.
- **Haptics:** iOS-only, guarded by `process.env.EXPO_OS === 'ios'`.
- **Notifications:** Return early on web (`Platform.OS === 'web'`).

## Key Constants

- **`constants/habits.ts`** — `Habit` interface, `HABIT_LIBRARY` array (8 habits: speed-sticks, driver, gym, cardio, core, meals, h2o, alcohol), `CATEGORY_META` for ring colors/labels
- **`constants/speed-protocols.ts`** — `SpeedSession` interface (14 fields: normalStance/stepDrill per stick color dom+nonDom, maxOut green+driver)
- **`constants/strength-protocols.ts`** — `WorkoutDay` type (legs1/pull/legs2/push), `WORKOUT_DAYS` with exercise definitions, `ExerciseSet`/`ExerciseLog`/`StrengthSession` interfaces
- **`constants/challenges.ts`** — `ChallengeTemplate` interface, predefined challenge templates

## File Organization

**Never store screenshots or images (png, jpg, svg, etc.) in the project root directory.** All images belong in `public/images/` with subfolders by category. Screenshots taken during testing or development must not be committed to the repo at all — delete them after use.

## Key Conventions

- **Stale closure prevention:** Speed and strength screens use `useRef` for session state in callbacks to avoid stale closures with `useCallback`
- **Sound system:** `constants/sounds.ts` pre-loads audio assets; respects `profile.soundEnabled`
- **Migration:** `utils/migration.ts` converts old `habits-YYYY-MM-DD` format to `habit-logs-YYYY-MM-DD` on first launch
- **Dev tools:** Settings screen has date override, data generation, and clear-all for testing
